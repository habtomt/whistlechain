## 2. Final technical assumptions (non-blocking decisions)

| Area | Decision | Why |
|---|---|---|
| Solidity version | `0.8.24` | 
| Node.js | `>=18` (tested on Node 22) | Required by Hardhat 2.x / ethers v6. |
| Hardhat version | `2.29.x` (not Hardhat 3) | Hardhat 3 requires an ESM-only project layout and a different config/test API; 
| Reward/stake token | (`UZH Ethereum POS`, symbol `UZHETHs`) If other ERC-20 test token address, swap it in by deploying `Treasury`/`ReportRegistry` with that token's address. |
| Gas currency | Native `UZHETHs` on the UZH Ethereum PoS network |
| **Encrypted report content storage** | On-chain
| **Validator admission** | **Fully self-service and permissionless**|
| **Validator probation ramp** | New validators' voting power ramps linearly from **20% to 100%** of their raw reputation weight over their first **5 lifetime votes** |
| Frontend framework | **Plain HTML/CSS/JS using ethers.js v6 via CDN** |

## 4. Cryptography implementation (summary)

See `frontend/crypto.js` for full inline documentation. Summary:

- **Key generation:** `crypto.subtle.generateKey({name:"AES-GCM", length:256}, ...)`, exported as raw bytes and base64-encoded for display/sharing (the key itself is never put on-chain).
- **Key storage:** the key is **never stored anywhere** by the app — it is shown once to the whistleblower after submission and must be copied and shared with the validator committee through a channel outside this application and outside the blockchain. 
- **Key access:** a validator pastes the key into the "Review & Decrypt" panel locally in their own browser

## 5. Deployment — instructions

### 5.1 Prerequisites
- Node.js **18+** (tested with Node 22.22.2)
- npm 10+
- MetaMask (or another injected-wallet browser extension) for using the frontend
- A terminal

### 5.2 Install dependencies
```bash
npm install
```

### 5.3 Environment variables
```bash
cp .env.example .env
# Defaults already point at the UZH Ethereum PoS test network
# need to add:
#   DEPLOYER_PRIVATE_KEY=<your funded test account's private key>
# before running npm run deploy:uzh. Leave it blank for local-only testing.
```

### 5.4 Compile
```bash
npm run compile
```

### 5.5 Run tests
```bash
npm test

### 5.6 Local end-to-end deployment (requires local execution)
Terminal 1 — start a persistent local chain:
```bash
npx hardhat node
```
Terminal 2 — deploy all 5 contracts, wire them together, self-register 3 demo
validators (each pays JOIN_COST from deployer-provided demo funds, exactly
like a real user would with their own funds), and seed the treasury:
```bash
npm run deploy:local
```
This writes `deployments/localhost.json` and copies ABIs + addresses into
`frontend/contracts/` automatically.

Import one of the printed Hardhat test account private keys into MetaMask
and add a custom network pointing at `http://127.0.0.1:8545` (chain ID
`31337`).

### 5.7 Start the frontend (requires local execution)
```bash
npm run frontend
```
This serves the `frontend/` folder as static files on `http://localhost:5173`
(a static file server is required — opening `index.html` directly via
`file://` will not work because browsers block `fetch()` of local JSON files
under that protocol).

### 5.8 UZH Ethereum PoS test network deployment
1. Add `DEPLOYER_PRIVATE_KEY` to `.env` (`https://rpc.uzheths.ifi.uzh.ch`, chain ID `70207`).
2. Fund the deployer address with native `UZHETHs` 
3. Deploy:
   ```bash
   npm run deploy:uzh
   ```
4. This writes `deployments/uzh.json` + refreshes `frontend/contracts/`.
5. In MetaMask, click **"Add UZH_ETH_PoS to MetaMask"** in the frontend's
   wallet bar (or add it manually: Network Name `UZH_ETH_PoS`, RPC URL
   `https://rpc.uzheths.ifi.uzh.ch`, Chain ID `70207`, Currency Symbol
   `UZHETHs`, Block Explorer `https://explorer.uzheths.ifi.uzh.ch`), then
   repeat step 5.7.

**This step requires running the command against the live UZH
Ethereum PoS network. only the deployer's funded private key and the
resulting contract addresses remain to be filled in after run the
command.

## 6. End-to-end workflow

1. **Whistleblower tab:** click "Generate Fresh Wallet" (or connect MetaMask
   with a funded account). Fund the address with UZHETHs and native gas token if
   it's a freshly generated wallet. Fill in the report form and submit — this
   hashes + encrypts the report client-side, escrows the stake, and records
   the commitment on-chain. Copy the printed decryption key somewhere safe.
2. **Validator tab:** connect a wallet (any wallet — admission is open). If
   it isn't already a validator, click **"Approve 20  UZHETHs & Join as
   Validator"** — this is fully self-service, no admin approves it. Click
   "Refresh Report List", open the new report, paste the decryption key
   shared in step 1, click "Decrypt & Review" (the app also re-hashes the
   plaintext and confirms it matches the on-chain commitment), then cast an
   Approve or Reject vote. Note that a brand-new validator's first vote only
   counts at 20% power — the "Reputation" line at the top of the tab shows
   the current probation status and effective weight. Repeat with two more
   validator accounts (`deploy.js` self-registers 3 demo validators
   automatically) to have enough participating weight to reach quorum.
3. Wait for the 4-day voting period to elapse (on a local Hardhat network you
   can fast-forward time with `npx hardhat console` and
   `await network.provider.send("evm_increaseTime", [4*24*60*60+1])` followed
   by `await network.provider.send("evm_mine")`), then click "Finalize".
4. **Treasury & Governance tab:** see the updated treasury balance (which
   also includes any validator join fees collected), validator reputation
   changes, and the settled report outcome (reward paid + stake refunded, or
   stake forfeited).
